## 5. Reference comparison

`results/reference_comparison.csv`, generated by `scripts/reference_comparison.py`.

**Root-cause finding (from the governing-rule interface inspection, not
assumed):** the task's boxed reference values are reproduced verbatim by
the installed package's own bundled documentation
(`primat-0.3.1.dist-info/METADATA`) under a *different* worked example —
`primat --Omegabh2 0.02242 --network large --amax 8` — not by
`PRIMATConfig` defaults (`Omegabh2=0.022425`, `network=small`).

| Comparison | Observable | Δ_X | δ_X (relative) |
|---|---|---|---|
| baseline (network=small) vs. boxed reference | N_eff | −1.442e-09 | 4.74e-10 |
| | Y_P(BBN) | +7.680e-06 | 3.11e-05 |
| | D/H | −1.485e-08 | 6.10e-04 |
| documented example (network=large, amax=8) vs. boxed reference | N_eff | −1.442e-09 | 4.74e-10 |
| | Y_P(BBN) | +9.320e-06 | 3.77e-05 |
| | D/H | +8.422e-10 | 3.46e-05 |

Reproducing the documented example reduces the D/H discrepancy by a
factor of ~18 (6.10e-4 → 3.46e-5), confirming that the majority of the
D/H (and part of the Y_P) gap between the task-mandated baseline and the
boxed reference is explained by **network choice** (`small` vs.
`large, amax=8`), a documented, expected cause — not a software bug. N_eff
is essentially insensitive to network choice in both cases, as expected
(it is set almost entirely by neutrino-decoupling background physics, not
by the nuclear reaction network).

The small residual remaining even for the documented-example reproduction
(Y_P: 3.77e-5 relative, D/H: 3.46e-5 relative) is of the same order as
the independently measured C-vs-Python backend gap (§6: Y_P 2.69e-5,
D/H 2.18e-5 relative) — consistent with (though not proof of) the
reference text having been generated under a different backend resolution
than `auto` produces on this installation. This residual is small,
understood in kind if not in exact origin, and does not indicate a
software defect.

## 16. Numerical limitations

Distinguishing the three uncertainty sources this audit touched, kept
separate throughout (never summed together into one number):

- **Numerical uncertainty** (solver tolerance, weak-rate sampling
  resolution, backend implementation): quantified in §6-9. All numerical
  variation tested is CONVERGED — negligible against the physical/MC
  uncertainty scale (§7-8's η_X ≪ 1 throughout).
- **Physical/model uncertainty** (nuclear reaction rates, neutron
  lifetime): quantified by the N=1000 MC sample covariance C_theory
  (§10-12) — the only uncertainty source entering χ² from the theory side.
- **Observational uncertainty** (measured Y_P/D-H): the task-specified
  diagonal σ values (§14) — the only uncertainty source entering χ² from
  the observational side, with the explicit, stated limitation that no
  observational Y_P–D/H covariance is available.

Known unresolved items, all documented rather than papered over:
- The installed package's own test suite documents an unresolved ~1.7e-8
  absolute (~7e-4 relative) C/Python D/H gap for `network="small"` at
  default settings (root cause not yet identified upstream); this audit's
  own measured gap (5.3e-10 absolute, 2.18e-5 relative) is well inside that
  documented (still generous) budget, so it does not affect any conclusion
  here.
- No per-sample nuclear-rate-offset/τ_n values are retrievable from the
  public MC interface (§10), so only the resulting observable-level MC
  samples could be preserved and audited, not the underlying rate draws.
- No observational Y_P–D/H covariance was available (§14); the χ² in §15
  therefore uses a diagonal C_obs only, an explicit limitation, not an
  invented value.
